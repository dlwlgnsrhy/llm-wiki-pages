    에이전틱 엔지니어링 다섯 단계

    프롬프트를 잘 쓰는 것에서 시작해, 지금은 열세 개의 작업 공간이 동시에 돈다. 그 사이에 다섯 번의 단계 전환이 있었고, 전환마다 저장소에 흔적이 남았다.

    이 문서는 그 흔적만으로 쓴다. 커밋 수, 파일이 처음 들어온 날짜, 브랜치 구조 — 전부 git으로 다시 확인할 수 있는 값이다.

    단계는 교체되지 않는다GitHub에서 피드백 남기기

    다섯 단계의 정의는 Contract Loop Graph Harness v1에서 확정한 문장을 그대로 쓴다.

    하는 일
    Prompt 이번 행동을 지시한다
    Context 판단에 필요한 정보만 제공한다
    Harness 도구, 상태, 권한, 테스트, 기록을 묶는다
    Loop 관찰 결과를 다음 행동에 반영한다
    Graph 여러 행동의 의존성, 분기, 병렬성을 명시한다

    각 용어는 앞 단계를 없애지 않는다. 뒤 단계가 생겨도 앞 단계는 계속 필요하다. 그래서 아래 그림은 타임라인이 아니라 지층이다 — 한 번 시작된 띠는 끝까지 남는다.

    그래서 네 개의 루프를 분리했다 — 실행, 검증, 사건, 학습. 실행 성공과 검증 성공을 다른 상태로 기록하고, 검증에 실패하면 사람이 할 일 목록으로 돌아온다.

    5 · Graph — 열세 개가 동시에 돈다이 단계 경험 기록GitHub에서 피드백 남기기

    지금은 하나의 저장소 위에서 열세 개의 작업 공간이 병렬로 돈다. main 하나, 부서 다섯, 기능 브랜치 일곱. 부서는 고정 dept/* 브랜치에 물리 워크트리가 붙는다.

    부서 제도를 어떻게 설계했는지는 멀티에이전트 5부서에 있다.

    병렬은 숫자에서 먼저 보인다

    커밋을 세는 방법이 두 가지다. main만 세면 1,185건, 브랜치까지 세면 1,326건. 차이 141건이 아직 병합되지 않은 채 열두 개 레인에 흩어져 있다.

    두 선은 2026년 5월까지 완전히 겹친다. 6월부터 벌어진다. 그때가 작업이 여러 갈래로 갈라지기 시작한 시점이고, 벌어진 폭이 곧 병렬 작업량이다.

    이 문서의 다른 수치는 main 기준이다. 두 기준을 섞지 않기 위해 명시한다.
